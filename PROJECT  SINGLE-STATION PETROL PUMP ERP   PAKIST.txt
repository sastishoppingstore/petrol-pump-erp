# PROJECT: SINGLE-STATION PETROL PUMP ERP — PAKISTAN EDITION
# Stack: PHP 8.3 + Laravel 12 + MySQL only. Deployment target: StackCP (20i shared hosting).

====================================================================
PART 0 — GOLDEN RULES (READ FIRST, NEVER BREAK)
====================================================================
0.1  ONE PETROL PUMP ONLY. This is NOT multi-branch, NOT multi-tenant, NOT SaaS.
     No tenant_id, no branch_id, no company switcher anywhere. Station details
     (name, address, NTN, STRN, logo, OMC brand) live in a single `settings` record.
0.2  ONLY PHP. No React, Vue, Node runtime, npm build on the server, Redis,
     Supervisor, Docker, WebSocket servers, or Python scripts.
     Allowed frontend: Laravel Blade + Livewire 3 + Alpine.js + Tailwind CSS
     + Chart.js + plain CSS 3D transforms, all shipped as PRE-BUILT static files
     in /public (Tailwind compiled locally, committed as app.css; Livewire/Alpine/Chart.js
     served from local files, no CDN dependency so it works on weak internet).
0.3  ONE CONNECTED SYSTEM. Every module uses the same accounting engine, stock engine,
     shift engine and audit engine. No module edits a balance directly. Balances are
     always DERIVED from ledger transactions.
0.4  NO fake data, NO placeholder buttons, NO hard-coded figures. Every tile, number,
     chart and button on every screen must read from / write to the real database
     through real business logic. Demo seeders are allowed only for first-time setup and
     must be removable.
0.5  EASE OF USE IS THE #1 REQUIREMENT. The owner or cashier may be barely literate.
     If a screen needs explanation, it is designed wrong. (See PART 3.)
0.6  A feature is "done" only when: UI → validation → Livewire/controller → service →
     DB → accounting → stock → shift → audit → permission → report → notification →
     PDF/email (where needed) all work AND have tests.
